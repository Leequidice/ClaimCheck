Project: Claim Check. A Python CLI agent that audits a company’s public claims. Input: a company URL or pasted pitch text. Output: a report where every checkable claim is labeled verified, contradicted, or unverifiable, with evidence, source, and confidence.

Hard requirements

Pipeline: (a) extract atomic, checkable claims from the text (headcount, funding, founding year, location, founder backgrounds, customer counts); (b) for each claim, plan which evidence source to query; (c) fetch evidence from the Crustdata API (read the current docs for company enrichment and people endpoints; do not guess field names); (d) when sources disagree, decide which to trust and record the reasoning; (e) emit a verdict.
Reasoning rules: treat claims as ranges, not exact numbers (e.g. “40 employees” vs. 46 in the data is verified; vs. 120 is contradicted). Never mark a claim verified without at least one cited data point. Use “unverifiable” when evidence is missing instead of guessing.
State and recovery: save progress per claim to JSON so a crashed run resumes. Retry failed API calls with backoff. A single failed claim must not abort the whole run.
Verification step: a second independent pass re-checks every “verified” verdict by looking for contradicting evidence before the report is finalized.
Models: call models through the LiteLLM OpenAI-compatible endpoint with the team key. Keep calls cheap; the budget is $20 total.
neatlogs: pip install neatlogs, call neatlogs.init(...) from the first commit, and read docs.neatlogs.com and the hackathon skill for setup. Every claim’s verdict path should appear as traceable spans.
Entire: set up Entire in the repo following its docs and commit through it, so each AI-made change carries a checkpoint.
Evaluation harness (most important): build eval/ containing about 20 real companies with ground-truth values I will supply, plus altered copies with planted lies (inflated headcount, fake funding round, false founding year). Report precision, recall, and false-alarm count per run. Save every run’s results so runs can be compared.
README: setup, a demo run, eval results table, and a “before/after a fix” section with neatlogs trace screenshots.

Order of work: (1) Crustdata client and one working enrichment call, (2) claim extractor, (3) end-to-end on one company, (4) state and resume, (5) verification pass, (6) eval harness, (7) polish. Commit small. Ask me before adding scope.
